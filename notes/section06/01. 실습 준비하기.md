# Section 6 - 1. 실습 준비하기

**1. React 실습 프로젝트 생성**

Vite로 React 프로젝트를 만든다.

```bash id="r61a"
npm create vite@latest
```

이번 실습 설정:

```text id="r61b"
Framework → React
Variant   → JavaScript
```

프로젝트 생성 후:

```bash id="r61c"
cd 프로젝트명
npm install
npm run dev
```

---

**2. src 폴더 정리**

Vite 기본 예제 중 사용하지 않는 파일과 코드를 정리한다.

예를 들어 `App.css`를 삭제했다면 관련 `import`도 함께 제거해야 한다.

```jsx id="r61d"
import "./App.css";
```

삭제한 파일을 계속 import하면 오류가 발생할 수 있다.

---

**3. ESLint**

ESLint는 JavaScript와 React 코드에서 문제가 될 수 있는 부분을 검사하는 도구이다.

VSCode의 ESLint Extension을 설치하면 검사 결과를 에디터에서 바로 확인할 수 있다.

현재 실습에서는 일부 규칙을 끈다.

```javascript id="r61e"
rules: {
  "no-unused-vars": "off",
  "react/prop-types": "off",
}
```

---

**4. 주요 ESLint 규칙**

### a. `no-unused-vars`

사용하지 않는 변수를 검사한다.

```javascript id="r61f"
const name = "이정환";
```

`name`을 사용하지 않으면 경고가 발생할 수 있다.

현재 실습에서는 해당 검사를 끈다.

### b. `react/prop-types`

React 컴포넌트의 props에 `PropTypes`가 정의되어 있는지 검사하는 ESLint 규칙이다.

```jsx id="r61g"
function User({ name }) {
  return <div>{name}</div>;
}
```

현재 JavaScript React 실습에서는 PropTypes를 사용하지 않기 때문에 이 규칙도 끈다.

---

**5. PropTypes와 TypeScript**

둘은 서로 다른 방식이다.

```text id="r61h"
PropTypes
→ JavaScript React에서 props 타입 확인

TypeScript
→ 정적 타입 시스템

react/prop-types
→ PropTypes 사용 여부를 검사하는 ESLint 규칙
```

`react/prop-types`는 TypeScript 설정이 아니다.

---

**6. ESLint 규칙 값**

```text id="r61i"
off
→ 검사하지 않음

warn
→ 경고

error
→ 오류
```

---

**7. 핵심 정리**

* Vite로 `React + JavaScript` 프로젝트를 생성한다.
* 사용하지 않는 기본 파일과 import를 정리한다.
* ESLint는 코드 문제를 검사하는 도구이다.
* `no-unused-vars`는 사용하지 않는 변수를 검사한다.
* `react/prop-types`는 PropTypes 관련 React ESLint 규칙이다.
* 현재 실습에서는 두 규칙을 `off`로 설정한다.
* `react/prop-types`와 TypeScript는 서로 다른 개념이다.
