# Section 6 - 7. State와 Props

**1. State와 Props**

React 컴포넌트의 UI는 `state`와 `props`에 따라 달라질 수 있다.

```text
State
→ 컴포넌트가 직접 관리하는 값

Props
→ 부모에게 전달받는 값
```

---

**2. 컴포넌트가 리렌더링되는 주요 경우**

현재 단계에서는 다음 3가지를 기억하면 된다.

### a. 자신의 State가 변경될 때

```jsx
setCount(count + 1);
```

```text
State 변경
→ 해당 컴포넌트 리렌더링
```

### b. 전달받는 Props가 변경될 때

```jsx
<Child count={count} />
```

부모의 `count`가 변경되면 자식은 새로운 Props를 기준으로 다시 렌더링된다.

### c. 부모 컴포넌트가 리렌더링될 때

부모가 다시 렌더링되면 그 안의 자식 컴포넌트들도 기본적으로 다시 렌더링될 수 있다.

```text
부모 리렌더링
→ 자식 컴포넌트도 렌더링
```

---

**3. State를 사용하는 컴포넌트 가까이에 두기**

서로 관련 없는 State를 하나의 컴포넌트에서 모두 관리할 필요는 없다.

예를 들어 다음 두 상태가 있다고 하자.

```text
light
→ 전구 상태

count
→ 카운터 상태
```

각 상태를 실제로 사용하는 컴포넌트로 분리할 수 있다.

```text
App
├─ Bulb
│  └─ light
└─ Counter
   └─ count
```

이렇게 하면 각 컴포넌트의 역할과 State의 책임이 명확해진다.

---

**4. Bulb와 Counter**

`Bulb`는 `light` State만 관리한다.

```jsx
const [light, setLight] = useState("OFF");
```

```text
light 변경
→ Bulb 리렌더링
```

`Counter`는 `count` State만 관리한다.

```jsx
const [count, setCount] = useState(0);
```

```text
count 변경
→ Counter 리렌더링
```

`App`은 두 컴포넌트를 조합하는 역할만 한다.

```jsx
function App() {
  return (
    <>
      <Bulb />
      <Counter />
    </>
  );
}
```

---

**5. State와 Props 차이**

```text
State
→ 컴포넌트가 직접 관리
→ setState 함수로 변경

Props
→ 부모가 자식에게 전달
→ 자식은 전달받은 값을 사용
```

둘 다 컴포넌트가 어떤 UI를 렌더링할지 결정하는 데이터이다.

---

**6. 핵심 정리**

* State는 컴포넌트가 직접 관리하는 값이다.
* Props는 부모에서 자식으로 전달되는 값이다.
* State가 변경되면 해당 컴포넌트가 리렌더링된다.
* 새로운 Props를 받으면 자식 컴포넌트가 다시 렌더링될 수 있다.
* 부모가 리렌더링되면 자식도 기본적으로 다시 렌더링될 수 있다.
* 서로 관련 없는 State는 역할에 맞는 컴포넌트로 분리할 수 있다.
* State는 실제로 사용하는 컴포넌트 가까이에 두면 구조와 책임을 이해하기 쉽다.
