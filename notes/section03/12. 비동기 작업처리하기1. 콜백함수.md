# Section 3 - 12. 비동기 작업 처리하기 1. 콜백 함수

**1. 콜백으로 비동기 결과 받기**

비동기 작업의 결과는 작업이 끝난 뒤 **콜백 함수를 호출하면서 전달**할 수 있다.

```javascript id="b5v8m2"
function add(a, b, callback) {
  setTimeout(() => {
    const sum = a + b;
    callback(sum);
  }, 1000);
}

add(1, 2, (value) => {
  console.log(value); // 3
});
```

흐름은 다음과 같다.

```text id="n2p4qw"
비동기 작업 시작
→ 작업 완료
→ callback(결과)
→ 결과 사용
```

---

**2. 비동기 작업을 순서대로 연결하기**

이전 작업의 결과가 다음 작업에 필요하다면 콜백 안에서 다음 비동기 함수를 호출할 수 있다.

```javascript id="r8f1xa"
function orderFood(callback) {
  setTimeout(() => {
    callback("떡볶이");
  }, 1000);
}

function cooldownFood(food, callback) {
  setTimeout(() => {
    callback(`식은 ${food}`);
  }, 1000);
}

function freezeFood(food, callback) {
  setTimeout(() => {
    callback(`냉동된 ${food}`);
  }, 1000);
}
```

작업을 순서대로 연결하면 다음과 같다.

```javascript id="w7h3cd"
orderFood((food) => {
  console.log(food);

  cooldownFood(food, (cooldownedFood) => {
    console.log(cooldownedFood);

    freezeFood(cooldownedFood, (freezedFood) => {
      console.log(freezedFood);
    });
  });
});
```

실행 순서:

```text id="m6y2tk"
떡볶이
→ 식은 떡볶이
→ 냉동된 식은 떡볶이
```

---

**3. 콜백 지옥**

비동기 작업을 콜백으로 계속 연결하면 중첩이 깊어진다.

```javascript id="q9k0ls"
first((result1) => {
  second(result1, (result2) => {
    third(result2, (result3) => {
      console.log(result3);
    });
  });
});
```

이처럼 콜백이 계속 중첩되어 코드가 복잡해지는 것을 **콜백 지옥(Callback Hell)**이라고 한다.

주요 문제는 다음과 같다.

* 실행 흐름을 파악하기 어려움
* 들여쓰기가 깊어짐
* 수정과 오류 처리가 복잡해짐

이 문제를 개선하기 위해 이후에 `Promise`와 `async/await`를 사용한다.

---

**4. 핵심 정리**

* 비동기 작업이 끝난 뒤 콜백으로 결과를 전달할 수 있다.
* `callback(result)` 형태로 결과를 넘긴다.
* 이전 작업의 결과가 필요하면 콜백 안에서 다음 비동기 작업을 실행할 수 있다.
* 비동기 작업이 많아지면 콜백 중첩이 깊어질 수 있다.
* 이런 구조를 콜백 지옥이라고 한다.
* 콜백 지옥은 `Promise`, `async/await`로 개선할 수 있다.
