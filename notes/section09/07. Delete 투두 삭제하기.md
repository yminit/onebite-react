# Section 9 - 6. Update 투두 수정하기

**1. 이번 단계의 목표**

이번 단계에서는 CRUD의 **Update**, 즉 Todo의 완료 상태 `isDone`을 수정한다.

```text id="u1"
false ↔ true
```

체크박스를 클릭하면 해당 Todo의 완료 여부를 반대로 변경한다.

---

**2. Update 전체 흐름**

```text id="u2"
체크박스 클릭
→ TodoItem에서 id 확인
→ onUpdate(id)
→ App의 onUpdate 실행
→ 수정할 Todo 찾기
→ isDone 반전
→ todos State 변경
→ 화면 업데이트
```

핵심은 **수정할 Todo의 `id`와 `onUpdate` 함수가 컴포넌트 사이에서 어떻게 전달되는지** 이해하는 것이다.

---

**3. onUpdate는 App에서 관리**

`todos` State가 `App`에 있으므로 수정 함수도 `App`에 둔다.

```jsx id="u3"
const onUpdate = (targetId) => {
  setTodos(
    todos.map((todo) => {
      if (todo.id === targetId) {
        return {
          ...todo,
          isDone: !todo.isDone,
        };
      }

      return todo;
    })
  );
};
```

`targetId`는 수정할 Todo를 구분하는 `id`이다.

---

**4. map()으로 특정 Todo 수정하기**

```text id="u4"
todos
→ map()
→ id 비교
→ 수정 대상만 변경
→ 새로운 배열 생성
```

수정 대상인지 확인한다.

```jsx id="u5"
todo.id === targetId
```

대상이라면 기존 값을 복사하고 `isDone`만 변경한다.

```jsx id="u6"
{
  ...todo,
  isDone: !todo.isDone,
}
```

대상이 아니라면 그대로 반환한다.

```jsx id="u7"
return todo;
```

즉, 기존 State를 직접 수정하지 않고 **새로운 배열과 객체를 생성한다.**

---

**5. 완료 상태 반전하기**

```jsx id="u8"
isDone: !todo.isDone
```

```text id="u9"
false → true
true  → false
```

`!` 연산자로 현재 Boolean 값을 반대로 바꾼다.

---

**6. onUpdate 전달하기**

체크박스는 `TodoItem`에 있으므로 함수가 다음 경로로 전달된다.

```text id="u10"
App
↓
List
↓
TodoItem
```

`App`:

```jsx id="u11"
<List
  todos={todos}
  onUpdate={onUpdate}
/>
```

`List`:

```jsx id="u12"
<TodoItem
  key={todo.id}
  {...todo}
  onUpdate={onUpdate}
/>
```

---

**7. TodoItem에서 수정 요청**

체크박스가 변경되면 현재 Todo의 `id`를 전달한다.

```jsx id="u13"
const onChangeCheckbox = () => {
  onUpdate(id);
};
```

```jsx id="u14"
<input
  type="checkbox"
  checked={isDone}
  onChange={onChangeCheckbox}
/>
```

`TodoItem`이 State를 직접 수정하는 것이 아니라, 부모에게 받은 함수를 호출한다.

---

**8. 전체 데이터 흐름**

```text id="u15"
체크박스 클릭
→ onUpdate(id)
→ App
→ todos.map()
→ id 비교
→ isDone 반전
→ setTodos()
→ todos 변경
→ 리렌더링
→ 체크박스 상태 변경
```

---

**9. Read와 Update에서 map()의 차이**

```text id="u16"
Read
→ 배열을 TodoItem UI로 변환

Update
→ 배열을 수정된 새로운 배열로 변환
```

배열 State에서 특정 항목을 수정할 때 자주 사용하는 패턴이다.

---

**10. 핵심 정리**

* 이번 단계는 CRUD의 `Update` 구현이다.
* 수정하는 값은 Todo의 `isDone`이다.
* 수정할 Todo를 찾기 위해 `id`를 사용한다.
* `onUpdate`는 `todos` State를 관리하는 `App`에 둔다.
* `onUpdate`는 `App → List → TodoItem`으로 Props를 통해 전달된다.
* `TodoItem`은 `onUpdate(id)`로 수정 요청을 보낸다.
* `map()`으로 전체 배열을 순회하면서 수정 대상을 찾는다.
* 수정 대상은 `{ ...todo, isDone: !todo.isDone }`으로 새 객체를 만든다.
* 기존 State를 직접 수정하지 않는다.
* 핵심 흐름은 **`체크박스 → onUpdate(id) → map() → isDone 변경 → setTodos()`**이다.
