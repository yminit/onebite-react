# Section 9 - 2. UI 구현하기

**1. 이번 단계의 목표**

이번 단계는 Todo List의 기능보다 **UI 구조를 먼저 설계하는 단계**이다.

```text
전체 영역 나누기
→ 컴포넌트 분리
→ 계층 구조 구성
→ 스타일 적용
→ 이후 기능 연결
```

---

**2. 전체 컴포넌트 구조**

Todo List는 다음처럼 나눈다.

```text
App
├─ Header
├─ Editor
└─ List
   └─ TodoItem
```

각 역할은 다음과 같다.

```text
Header
→ 오늘 날짜 표시

Editor
→ Todo 입력 및 추가

List
→ 검색과 Todo 목록 표시

TodoItem
→ Todo 하나의 UI
```

---

**3. App의 역할**

`App`은 세부 UI를 직접 모두 작성하기보다 **전체 컴포넌트를 조합하는 역할**을 한다.

```text
App
→ 전체 페이지 구조

Header / Editor / List
→ 각 영역의 실제 UI
```

이렇게 나누면 전체 화면 구조를 빠르게 파악할 수 있다.

---

**4. 반복되는 UI는 컴포넌트로 분리**

Todo 목록에서는 같은 형태의 항목이 반복된다.

```text
List
├─ TodoItem
├─ TodoItem
└─ TodoItem
```

따라서 하나의 Todo UI를 `TodoItem`으로 만들어 재사용한다.

```text
Todo 하나
→ TodoItem

Todo 여러 개
→ TodoItem 반복 렌더링
```

---

**5. 컴포넌트 분리 기준**

이번 화면에서는 다음 기준으로 나눈다.

```text
역할이 명확한가?
→ Header / Editor / List

독립적인 UI 영역인가?
→ 별도 컴포넌트

반복되는 UI인가?
→ TodoItem
```

컴포넌트를 너무 잘게 나누는 것이 목적이 아니라 **역할과 책임을 명확하게 만드는 것**이 중요하다.

---

**6. 레이아웃 구조**

전체 화면은 세로 방향으로 배치한다.

```text
Header
↓
Editor
↓
List
```

`Editor`는 입력창과 버튼을 가로로 배치한다.

```text
[ 새로운 Todo...        ] [추가]
```

`List` 내부는 다음처럼 구성한다.

```text
Todo List 🌱
검색창
TodoItem
TodoItem
TodoItem
```

---

**7. 스타일 관리**

각 컴포넌트의 스타일은 해당 컴포넌트와 관련된 CSS 파일로 분리한다.

```text
Header.jsx
↔ Header.css

Editor.jsx
↔ Editor.css

List.jsx
↔ List.css

TodoItem.jsx
↔ TodoItem.css
```

이렇게 하면 UI 코드와 관련 스타일의 위치를 찾기 쉽다.

---

**8. UI 구현 순서**

화면을 설계할 때 다음 순서로 생각하면 된다.

```text
1. 전체 화면을 큰 영역으로 나누기
2. 각 영역의 역할 정하기
3. 컴포넌트로 분리하기
4. 반복되는 UI 찾기
5. 컴포넌트 계층 구조 만들기
6. 레이아웃과 스타일 적용
7. State / Props / 이벤트 연결
```

---

**9. 핵심 정리**

* 이번 단계는 기능 구현 전 UI 구조 설계 단계이다.
* `App` 아래에 `Header`, `Editor`, `List`를 둔다.
* `Header`는 날짜를 표시한다.
* `Editor`는 Todo 입력과 추가 UI를 담당한다.
* `List`는 검색과 목록을 담당한다.
* 반복되는 Todo 하나는 `TodoItem`으로 분리한다.
* 컴포넌트는 역할과 책임을 기준으로 나눈다.
* UI 구조를 먼저 만든 뒤 State, Props, 이벤트를 연결한다.
* 기본 흐름은 **전체 영역 → 컴포넌트 → 계층 구조 → 스타일 → 기능**이다.
