# Section 9 - 3. 기능 구현 준비하기

**1. 이번 단계의 핵심**

이번 단계에서는 기능을 만들기 전에 **Todo 데이터를 어떤 구조로 관리할지 먼저 설계**한다.

```text
UI 구현
→ 데이터 모델링
→ State 구성
→ 추가 / 수정 / 삭제 기능 구현
```

---

**2. Todo 데이터 모델**

Todo 하나는 객체 하나로 표현한다.

```javascript
{
  id: 0,
  isDone: false,
  content: "React",
  date: new Date().getTime(),
}
```

각 값의 역할은 다음과 같다.

```text
id
→ Todo 식별값

isDone
→ 완료 여부

content
→ Todo 내용

date
→ 생성 시점
```

---

**3. 여러 Todo는 배열로 관리**

Todo는 여러 개 존재하므로 객체들을 배열에 저장한다.

```javascript
const mockData = [
  {
    id: 0,
    isDone: false,
    content: "React",
    date: new Date().getTime(),
  },
  {
    id: 1,
    isDone: false,
    content: "빨래하기",
    date: new Date().getTime(),
  },
  {
    id: 2,
    isDone: false,
    content: "노래하기",
    date: new Date().getTime(),
  },
];
```

```text
Todo 한 건
→ 객체

여러 Todo
→ 배열
```

`mockData`는 실제 사용자 데이터가 아니라 기능 구현 전 화면과 데이터 구조를 확인하기 위한 임시 데이터이다.

---

**4. Todo 목록은 State로 관리**

Todo 목록은 앞으로 추가, 수정, 삭제되므로 변경 가능한 데이터이다.

따라서 State로 관리한다.

```jsx
const [todos, setTodos] = useState(mockData);
```

```text
todos
→ 현재 Todo 목록

setTodos
→ Todo 목록 변경
```

State가 변경되면 변경된 데이터에 맞춰 화면도 다시 렌더링된다.

---

**5. State 위치 결정**

현재 구조는 다음과 같다.

```text
App
├─ Header
├─ Editor
└─ List
```

앞으로

```text
Editor
→ Todo 추가

List
→ Todo 목록 사용
```

처럼 여러 컴포넌트가 Todo 데이터와 관련된다.

따라서 `todos` State는 공통 부모인 `App`에서 관리한다.

```text
App
├─ todos State
├─ Header
├─ Editor
└─ List
```

앞에서 배운 **State Lifting**과 같은 기준이다.

---

**6. 데이터와 UI의 관계**

React에서는 UI만 설계하는 것이 아니라 **UI를 만드는 데이터 구조도 함께 설계해야 한다.**

```text
todos State
→ List
→ TodoItem
→ 화면
```

데이터가 변경되면 그 데이터를 사용하는 UI도 변경된다.

---

**7. 기능 구현 전 생각할 순서**

```text
1. 필요한 데이터 확인
2. 데이터 한 건의 구조 정의
3. 여러 데이터를 어떤 형태로 관리할지 결정
4. 변경되는 데이터인지 확인
5. 변경된다면 State로 관리
6. State를 관리할 컴포넌트 결정
7. Props와 이벤트 연결
```

이번 단계에서는 1~6까지 준비한 상태이다.

---

**8. 핵심 정리**

* 이번 단계의 핵심은 **데이터 모델링**이다.
* Todo 하나는 `id`, `isDone`, `content`, `date`를 가진 객체이다.
* 여러 Todo는 배열로 관리한다.
* `mockData`는 개발용 임시 데이터이다.
* Todo 목록은 추가, 수정, 삭제되므로 State로 관리한다.
* `todos`는 여러 컴포넌트가 사용하므로 공통 부모인 `App`에 둔다.
* React에서는 UI 구현 전에 **어떤 데이터를 어떤 구조로 관리할지 설계하는 과정**이 중요하다.
