# Section 10 - 2. 투두리스트 업그레이드

**1. 이번 단계의 핵심**

기존 Todo List의 `todos` 상태 관리를 `useState`에서 `useReducer`로 변경한다.

```text
기존
onCreate / onUpdate / onDelete
→ 각각 setTodos()

변경 후
onCreate / onUpdate / onDelete
→ dispatch(action)
→ reducer
→ todos 변경
```

핵심은 **상태 변경 로직을 App에서 reducer로 분리하는 것**이다.

---

**2. useReducer 적용**

```jsx
const [todos, dispatch] = useReducer(reducer, mockData);
```

```text
todos
→ 현재 Todo State

dispatch
→ 상태 변경 요청 전달

reducer
→ 실제 상태 변경 처리

mockData
→ 초기값
```

---

**3. reducer 구조**

Todo 상태 변경 규칙을 하나의 `reducer`에 모은다.

```jsx
function reducer(state, action) {
  switch (action.type) {
    case "CREATE":
      return [action.data, ...state];

    case "UPDATE":
      return state.map((item) =>
        item.id === action.targetId
          ? {
              ...item,
              isDone: !item.isDone,
            }
          : item
      );

    case "DELETE":
      return state.filter(
        (item) => item.id !== action.targetId
      );

    default:
      return state;
  }
}
```

```text
CREATE
→ Todo 추가

UPDATE
→ Todo 수정

DELETE
→ Todo 삭제
```

---

**4. CREATE**

`onCreate`는 직접 State를 수정하지 않고 Action을 보낸다.

```jsx
const onCreate = (content) => {
  dispatch({
    type: "CREATE",
    data: {
      id: idRef.current++,
      isDone: false,
      content,
      date: new Date().getTime(),
    },
  });
};
```

reducer에서는 다음 로직을 실행한다.

```jsx
case "CREATE":
  return [action.data, ...state];
```

```text
onCreate
→ dispatch(CREATE)
→ reducer
→ 새 Todo + 기존 todos
```

---

**5. UPDATE**

수정할 Todo의 `id`를 Action으로 전달한다.

```jsx
const onUpdate = (targetId) => {
  dispatch({
    type: "UPDATE",
    targetId,
  });
};
```

reducer:

```jsx
case "UPDATE":
  return state.map((item) =>
    item.id === action.targetId
      ? {
          ...item,
          isDone: !item.isDone,
        }
      : item
  );
```

```text
onUpdate
→ dispatch(UPDATE)
→ map()
→ id 비교
→ isDone 반전
```

---

**6. DELETE**

삭제할 Todo의 `id`를 전달한다.

```jsx
const onDelete = (targetId) => {
  dispatch({
    type: "DELETE",
    targetId,
  });
};
```

reducer:

```jsx
case "DELETE":
  return state.filter(
    (item) => item.id !== action.targetId
  );
```

```text
onDelete
→ dispatch(DELETE)
→ filter()
→ 대상 Todo 제외
```

---

**7. 기존 배열 처리 방식은 그대로**

`useReducer`를 사용한다고 State 변경 원리가 달라지는 것은 아니다.

```text
CREATE
[newTodo, ...todos]
→ [action.data, ...state]

UPDATE
todos.map(...)
→ state.map(...)

DELETE
todos.filter(...)
→ state.filter(...)
```

기존 State를 직접 수정하지 않고 **새로운 배열과 객체를 만들어 반환하는 불변성 원칙도 그대로 유지한다.**

---

**8. 자식 컴포넌트는 바뀌지 않는다**

`Editor`, `List`, `TodoItem`은 부모가 `useState`를 사용하는지 `useReducer`를 사용하는지 알 필요가 없다.

```text
Editor
→ onCreate(content)

TodoItem
→ onUpdate(id)
→ onDelete(id)
```

자식 컴포넌트 입장에서는 기존과 동일한 Props를 사용한다.

즉, **상태 관리의 내부 구현만 변경된 것**이다.

---

**9. 상태 변경 요청과 로직 분리**

`useReducer`에서 가장 중요한 구조이다.

```text
App
→ 무엇을 할 것인지 전달
→ dispatch(action)

reducer
→ 어떻게 State를 변경할지 결정
```

```text
이벤트
→ dispatch(action)
→ reducer
→ 새로운 todos
→ 리렌더링
```

---

**10. useState와 useReducer 선택 기준**

```text
단순한 State
→ useState

상태 변경 종류가 많거나
관련 로직이 복잡함
→ useReducer 고려
```

Todo처럼 `CREATE`, `UPDATE`, `DELETE` 등 여러 상태 변경 규칙이 있으면 reducer에 모아서 관리할 수 있다.

---

**11. 핵심 정리**

* 기존 `useState` 기반 Todo 관리를 `useReducer`로 변경한다.
* `dispatch`는 상태 변경 Action을 전달한다.
* `reducer`는 실제 상태 변경 방법을 결정한다.
* `CREATE`는 Spread를 이용해 Todo를 추가한다.
* `UPDATE`는 `map()`으로 특정 Todo를 수정한다.
* `DELETE`는 `filter()`로 특정 Todo를 제거한다.
* 기존 불변성 유지 방식은 그대로 사용한다.
* 자식 컴포넌트의 사용 방식은 거의 바뀌지 않는다.
* `useReducer`의 장점은 **상태 변경 요청과 실제 변경 로직을 분리할 수 있다는 것**이다.
* 핵심 흐름은 **`이벤트 → dispatch(action) → reducer → 새로운 State → 리렌더링`**이다.
