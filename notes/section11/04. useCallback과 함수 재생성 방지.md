# Section 11 - 4. useCallback과 함수 재생성 방지

**1. useCallback이란?**

`useCallback`은 **함수의 참조를 메모이제이션해서 불필요한 함수 재생성을 줄이는 Hook**이다.

```text
컴포넌트 리렌더링
→ 내부 함수 다시 생성 가능

useCallback 사용
→ 의존성이 같으면 기존 함수 재사용
```

---

**2. 기본 형태**

```jsx
const callback = useCallback(() => {
  // 실행할 코드
}, [의존성]);
```

```text
의존성 변경 없음
→ 기존 함수 참조 재사용

의존성 변경
→ 새로운 함수 생성
```

---

**3. Todo 프로젝트에 적용**

기존에는 `App` 안의 함수들이 리렌더링마다 다시 생성될 수 있었다.

```text
onCreate
onUpdate
onDelete
```

예를 들어:

```jsx
const onUpdate = useCallback((targetId) => {
  dispatch({
    type: "UPDATE",
    targetId,
  });
}, []);
```

`onDelete`도 같은 방식으로 적용할 수 있다.

---

**4. 왜 필요한가?**

`onUpdate`, `onDelete`는 `TodoItem`까지 Props로 전달된다.

```text
App
↓
List
↓
TodoItem
```

`TodoItem`에 `memo`가 적용되어 있더라도 함수 Props가 매번 새로운 함수라면 Props가 변경된 것으로 판단될 수 있다.

```text
App 리렌더링
→ 함수 새로 생성
→ 함수 참조 변경
→ TodoItem의 Props 변경
→ memo가 렌더링을 막지 못할 수 있음
```

따라서 함수 Props의 참조를 안정적으로 유지할 필요가 있을 때 `useCallback`을 사용한다.

---

**5. React.memo와 useCallback**

두 기능은 함께 사용되는 경우가 많다.

```text
React.memo
→ Props가 같으면 컴포넌트 렌더링 생략

useCallback
→ 함수 Props의 참조 유지
```

```text
useCallback
+
React.memo
→ 불필요한 자식 컴포넌트 렌더링 감소
```

---

**6. TodoItem의 memo 단순화**

이전에는 함수 Props가 계속 달라질 수 있어서 직접 비교 함수를 작성할 수 있었다.

`useCallback`으로 함수 참조까지 안정적으로 유지하면 기본 `memo` 비교를 사용할 수 있다.

```jsx
export default memo(TodoItem);
```

단, `memo`에 전달되는 **모든 Props가 실제로 안정적인지** 확인해야 한다.

---

**7. dispatch와 useCallback**

현재 `onUpdate`, `onDelete`는 `dispatch`만 사용한다.

```jsx
const onDelete = useCallback((targetId) => {
  dispatch({
    type: "DELETE",
    targetId,
  });
}, []);
```

`useReducer`의 `dispatch` 함수는 렌더링 사이에서 안정적인 참조를 가지므로 이런 함수는 빈 의존성 배열을 사용할 수 있다.

반면 콜백 내부에서 State나 Props 값을 사용한다면 해당 값을 의존성 배열에 포함해야 한다.

---

**8. 최적화 적용 순서**

최적화는 기능 구현보다 먼저 하는 것이 목적이 아니다.

```text
기능 구현
→ 정상 동작 확인
→ 성능 문제 확인
→ 필요한 부분 최적화
```

모든 함수에 `useCallback`을 적용하면 오히려 코드 복잡도와 메모이제이션 비용만 증가할 수 있다.

---

**9. 지금까지의 최적화 구분**

```text
useMemo
→ 계산 결과 메모이제이션

React.memo
→ 컴포넌트 렌더링 최적화

useCallback
→ 함수 참조 메모이제이션
```

특히 `useCallback`은 **함수 실행 자체를 빠르게 만드는 기능이 아니라 함수의 참조를 유지하는 기능**이라는 점이 중요하다.

---

**10. 핵심 정리**

* `useCallback`은 함수의 참조를 메모이제이션한다.
* 기본 형태는 `useCallback(함수, [의존성])`이다.
* 의존성이 같으면 이전 함수 참조를 재사용한다.
* 함수가 `memo`된 자식 컴포넌트에 Props로 전달될 때 특히 유용할 수 있다.
* `React.memo`와 함께 사용하면 불필요한 자식 렌더링을 줄이는 데 도움이 된다.
* 콜백이 사용하는 State나 Props는 의존성 배열에 포함해야 한다.
* 모든 함수에 무조건 적용할 필요는 없다.
* 핵심 구분은 **`useMemo = 값`, `memo = 컴포넌트`, `useCallback = 함수`**이다.
