# Section 11 - 1. 최적화란

**1. 최적화란?**

최적화는 **웹 서비스의 성능을 개선하는 작업 전체**를 의미한다.

```text
웹 서비스
→ 불필요한 작업 감소
→ 성능 개선
→ 더 빠르고 부드러운 사용자 경험
```

---

**2. 웹 서비스 전체에서의 최적화**

React뿐 아니라 웹 서비스 전체에서도 다양한 최적화가 가능하다.

```text
서버 응답 속도 개선
정적 파일 로딩 개선
불필요한 네트워크 요청 감소
```

예를 들어 이미지, 폰트, JavaScript, CSS 파일이 너무 크거나 서버 응답이 느리면 사용자가 화면을 기다리는 시간이 길어진다.

---

**3. React 내부 최적화**

React 애플리케이션에서는 주로 다음과 같은 불필요한 작업을 줄인다.

```text
React 최적화

├─ 불필요한 연산 줄이기
├─ 불필요한 함수 재생성 줄이기
└─ 불필요한 리렌더링 줄이기
```

---

**4. 불필요한 연산 줄이기**

컴포넌트가 리렌더링되면 컴포넌트 함수가 다시 실행된다.

```text
State 변경
→ 리렌더링
→ 컴포넌트 함수 다시 실행
→ 내부 연산도 다시 실행
```

비용이 큰 연산이 매번 다시 실행될 필요가 없다면 최적화 대상이 될 수 있다.

---

**5. 불필요한 함수 재생성 줄이기**

함수 컴포넌트가 다시 실행되면 내부에서 선언한 함수도 다시 생성된다.

```text
리렌더링
→ 컴포넌트 함수 실행
→ 내부 함수 다시 생성
```

필요한 경우 이러한 함수 재생성을 줄이는 것도 최적화 방법이 된다.

---

**6. 불필요한 리렌더링 줄이기**

부모가 리렌더링되면 자식 컴포넌트도 기본적으로 다시 렌더링될 수 있다.

```text
부모 리렌더링
→ 자식 렌더링
→ 실제 UI 변화 없음
→ 불필요한 렌더링 가능
```

실제 결과가 바뀌지 않는 컴포넌트의 렌더링을 줄이는 것이 React 최적화의 중요한 방향이다.

단, **리렌더링 자체가 항상 문제라는 뜻은 아니다.** 비용이 실제로 큰 경우에 최적화를 고려한다.

---

**7. 최적화의 기준**

최적화는 단순히 코드를 짧게 만드는 것이 아니다.

```text
코드가 짧음
≠ 성능 최적화

불필요한 작업 감소
→ 실제 성능 개선
→ 최적화
```

먼저 정상적으로 동작하는 코드를 만들고, 실제로 비용이 큰 부분을 확인한 뒤 최적화하는 것이 중요하다.

---

**8. 앞으로 연결될 내용**

앞으로 배우는 React 최적화 기능은 각각 줄이려는 대상이 다르다.

```text
불필요한 연산
→ useMemo

불필요한 함수 재생성
→ useCallback

불필요한 컴포넌트 리렌더링
→ React.memo
```

따라서 기능 자체보다 **무엇을 줄이기 위한 최적화인지**를 기준으로 이해하면 된다.

---

**9. 핵심 정리**

* 최적화는 웹 서비스의 성능을 개선하는 작업이다.
* 웹 전체에서는 서버, 파일 로딩, 네트워크 요청 등을 최적화할 수 있다.
* React에서는 불필요한 연산, 함수 재생성, 리렌더링을 줄이는 방향으로 최적화한다.
* 리렌더링이나 함수 재생성이 발생한다고 해서 무조건 최적화할 필요는 없다.
* 실제 비용이 있는 부분을 확인하고 필요한 곳에만 최적화를 적용하는 것이 중요하다.
* 핵심은 **불필요한 작업을 줄이는 것**이다.
