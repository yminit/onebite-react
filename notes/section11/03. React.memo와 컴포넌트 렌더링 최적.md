# Section 11 - 3. React.memo와 컴포넌트 렌더링 최적화

**1. React.memo란?**

`React.memo`는 **Props가 바뀌지 않은 컴포넌트의 불필요한 리렌더링을 줄이는 기능**이다.

```text
컴포넌트
→ memo()
→ 최적화된 컴포넌트
```

기본 사용법:

```jsx
import { memo } from "react";

export default memo(Header);
```

---

**2. 기본 동작**

`memo`는 이전 Props와 새로운 Props를 비교한다.

```text
Props 동일
→ 렌더링 생략 가능

Props 변경
→ 컴포넌트 다시 렌더링
```

즉, 부모가 리렌더링되더라도 해당 컴포넌트의 Props가 그대로라면 렌더링을 건너뛸 수 있다.

---

**3. TodoItem에 적용하기**

```jsx
export default memo(TodoItem);
```

Todo가 여러 개 있을 때 한 Todo만 변경되었다면, Props가 그대로인 다른 `TodoItem`의 불필요한 렌더링을 줄일 수 있다.

```text
Todo A 변경
→ Todo A 리렌더링

Todo B / Todo C
→ Props 동일
→ 렌더링 생략 가능
```

---

**4. 직접 Props 비교하기**

필요하면 두 번째 인수로 비교 함수를 전달할 수 있다.

```jsx
export default memo(
  TodoItem,
  (prevProps, nextProps) => {
    // 비교
  }
);
```

```text
prevProps
→ 이전 Props

nextProps
→ 새로운 Props
```

---

**5. 비교 함수 반환값**

반환값의 의미를 반대로 헷갈리지 않는 것이 중요하다.

```text
true
→ Props가 같다고 판단
→ 리렌더링 생략

false
→ Props가 다르다고 판단
→ 리렌더링
```

예:

```jsx
if (prevProps.id !== nextProps.id) {
  return false;
}

if (prevProps.isDone !== nextProps.isDone) {
  return false;
}

if (prevProps.content !== nextProps.content) {
  return false;
}

if (prevProps.date !== nextProps.date) {
  return false;
}

return true;
```

---

**6. 함수 Props도 중요하다**

`memo`는 컴포넌트가 전달받는 Props를 기준으로 판단한다.

따라서 `onUpdate`, `onDelete` 같은 **함수도 Props라면 비교 대상**이 된다.

```text
데이터 Props 동일
+
함수 Props가 새로 생성됨
→ Props가 달라졌다고 판단 가능
→ TodoItem 다시 렌더링
```

이 문제는 다음 단계에서 배우는 `useCallback`과 연결된다.

---

**7. HOC**

`memo`처럼 컴포넌트를 받아 새로운 컴포넌트를 반환하는 형태를 **고차 컴포넌트(HOC)**라고 한다.

```jsx
memo(TodoItem)
```

```text
컴포넌트
→ HOC
→ 새로운 컴포넌트
```

---

**8. useMemo와 React.memo 차이**

```text
useMemo
→ 계산 결과 메모이제이션
→ 불필요한 연산 감소

React.memo
→ 컴포넌트 메모이제이션
→ 불필요한 렌더링 감소
```

둘 다 메모이제이션을 사용하지만 **최적화 대상이 다르다.**

---

**9. 사용할 때 주의할 점**

`memo`를 모든 컴포넌트에 무조건 적용하는 것은 아니다.

Props 비교에도 비용이 있기 때문에 실제로 반복 렌더링 비용이 있는 컴포넌트에 적용하는 것이 좋다.

또한 `memo`는 주로 **Props 기반 리렌더링을 최적화**한다. 해당 컴포넌트가 사용하는 자신의 State나 Context가 변경되면 다시 렌더링될 수 있다.

---

**10. 핵심 정리**

* `React.memo`는 불필요한 컴포넌트 렌더링을 줄인다.
* 부모가 리렌더링되어도 Props가 동일하면 렌더링을 생략할 수 있다.
* 기본 형태는 `memo(Component)`이다.
* 필요하면 직접 Props 비교 함수를 작성할 수 있다.
* 비교 함수에서 `true`는 렌더링 생략, `false`는 리렌더링을 의미한다.
* Todo처럼 동일한 컴포넌트가 많이 반복될 때 활용할 수 있다.
* 함수 Props의 참조가 바뀌면 `memo` 최적화가 깨질 수 있다.
* 이 문제는 이후 `useCallback`과 연결된다.
* `useMemo`는 **연산**, `React.memo`는 **컴포넌트 렌더링**을 최적화한다.
