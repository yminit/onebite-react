# Section 7 - 3. 기능 구현하기

**1. State는 공통 부모에서 관리하기**

`Viewer`는 `count`를 보여주고, `Controller`는 `count`를 변경한다.

두 컴포넌트가 같은 State를 사용하므로 공통 부모인 `App`에서 관리한다.

```jsx id="p7ozqg"
const [count, setCount] = useState(0);
```

```text id="08q76g"
App
├─ count State
├─ Viewer
└─ Controller
```

---

**2. State Lifting**

여러 컴포넌트가 하나의 State를 공유해야 할 때 **가장 가까운 공통 부모로 State를 올리는 것**을 State Lifting이라고 한다.

```text id="lunl5a"
여러 컴포넌트가 State 공유
→ 공통 부모 찾기
→ 공통 부모에서 State 관리
```

---

**3. Viewer에 count 전달하기**

`App`의 `count`를 Props로 전달한다.

```jsx id="yotjqp"
<Viewer count={count} />
```

`Viewer`에서는 전달받은 값을 화면에 표시한다.

```jsx id="h8ty73"
const Viewer = ({ count }) => {
  return (
    <div>
      <div>현재 카운트 :</div>
      <h1>{count}</h1>
    </div>
  );
};
```

---

**4. Controller에서 count 변경하기**

State 자체는 `App`이 관리한다.

따라서 `App`에 State 변경 함수를 만든다.

```jsx id="s02ubm"
const onClickButton = (value) => {
  setCount(count + value);
};
```

그리고 이 함수를 `Controller`에 Props로 전달한다.

```jsx id="60ia04"
<Controller onClickButton={onClickButton} />
```

함수도 일반 값처럼 Props로 전달할 수 있다.

---

**5. Controller에서 함수 실행하기**

```jsx id="knpe50"
const Controller = ({ onClickButton }) => {
  return (
    <div>
      <button onClick={() => onClickButton(-1)}>-1</button>
      <button onClick={() => onClickButton(-10)}>-10</button>
      <button onClick={() => onClickButton(-100)}>-100</button>
      <button onClick={() => onClickButton(100)}>+100</button>
      <button onClick={() => onClickButton(10)}>+10</button>
      <button onClick={() => onClickButton(1)}>+1</button>
    </div>
  );
};
```

버튼마다 같은 함수를 사용하고 변경할 값만 다르게 전달한다.

---

**6. 전체 데이터 흐름**

```text id="uhmdkj"
Controller 버튼 클릭
→ onClickButton(value)
→ App의 setCount()
→ count 변경
→ App 리렌더링
→ 새로운 count를 Viewer에 전달
→ Viewer 화면 변경
```

`Controller`가 `App`의 State를 직접 수정하는 것이 아니라, 부모에게 전달받은 함수를 호출하는 구조이다.

---

**7. 단방향 데이터 흐름**

React에서 데이터는 기본적으로 **부모 → 자식** 방향으로 전달된다.

```text id="0h9c7a"
          App
       /       \
 count Props   onClickButton Props
     ↓               ↓
  Viewer         Controller
```

State의 실제 관리 주체는 계속 `App`이다.

---

**8. State 위치를 정하는 기준**

```text id="n2ezca"
한 컴포넌트만 사용
→ 해당 컴포넌트에서 State 관리

여러 컴포넌트가 공유
→ 가장 가까운 공통 부모에서 State 관리
```

이번 프로젝트에서는 `Viewer`와 `Controller`가 `count`를 함께 사용하므로 `App`이 관리한다.

---

**9. 핵심 정리**

* 여러 컴포넌트가 하나의 State를 공유하면 공통 부모에서 관리한다.
* 이를 State Lifting이라고 한다.
* `App`이 `count` State를 관리한다.
* `Viewer`는 `count`를 Props로 받아 화면에 표시한다.
* `Controller`는 State 변경 함수를 Props로 받는다.
* 함수도 Props로 전달할 수 있다.
* `Controller`는 부모의 State를 직접 수정하지 않고 전달받은 함수를 호출한다.
* React의 데이터는 기본적으로 부모에서 자식 방향으로 흐른다.
* State는 실제 사용하는 컴포넌트들의 가장 가까운 공통 부모에 두는 것이 기본 기준이다.
