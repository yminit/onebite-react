# Section 12 - 3. Context 분리하기

**1. 왜 Context를 분리할까?**

하나의 Context에 `todos`와 함수들을 모두 넣으면 `todos`가 변경될 때 Context 값도 변경된다.

```text
TodoContext
├─ todos
├─ onCreate
├─ onUpdate
└─ onDelete
```

이 경우 Context를 사용하는 컴포넌트들이 함께 리렌더링될 수 있다.

```text
todos 변경
→ Context value 변경
→ Context 사용 컴포넌트 리렌더링
```

---

**2. State와 Dispatch를 분리한다**

변경되는 데이터와 상대적으로 안정적인 함수를 서로 다른 Context로 나눈다.

```jsx
export const TodoStateContext = createContext();

export const TodoDispatchContext = createContext();
```

```text
TodoStateContext
→ todos

TodoDispatchContext
→ onCreate
→ onUpdate
→ onDelete
```

> 기존 코드의 `TodoDispatchContest`는 이름상 `TodoDispatchContext`를 의미하는 것으로 보면 된다.

---

**3. State Context**

`TodoStateContext`에는 변경되는 Todo 목록을 넣는다.

```jsx
<TodoStateContext.Provider value={todos}>
```

```text
Todo 추가 / 수정 / 삭제
→ todos 변경
→ TodoStateContext 값 변경
```

`todos`가 필요한 컴포넌트는 이 Context를 사용한다.

---

**4. Dispatch Context**

상태 변경 함수들은 별도의 Context에 넣는다.

```text
TodoDispatchContext
├─ onCreate
├─ onUpdate
└─ onDelete
```

각 함수는 `useCallback`으로 메모이제이션할 수 있다.

```jsx
const onUpdate = useCallback((targetId) => {
  dispatch({
    type: "UPDATE",
    targetId,
  });
}, []);
```

---

**5. Provider value 객체도 메모이제이션**

함수들이 그대로여도 다음 객체를 렌더링마다 직접 만들면 새로운 객체가 된다.

```jsx
{
  onCreate,
  onUpdate,
  onDelete,
}
```

따라서 `useMemo`로 객체 참조도 유지한다.

```jsx
const memoizedDispatch = useMemo(() => {
  return {
    onCreate,
    onUpdate,
    onDelete,
  };
}, [onCreate, onUpdate, onDelete]);
```

```text
useCallback
→ 함수 참조 유지

useMemo
→ 함수들을 담은 객체 참조 유지
```

---

**6. Provider 구조**

```jsx
<TodoStateContext.Provider value={todos}>
  <TodoDispatchContext.Provider value={memoizedDispatch}>
    <Editor />
    <List />
  </TodoDispatchContext.Provider>
</TodoStateContext.Provider>
```

구조는 다음과 같다.

```text
TodoStateContext
└─ todos
   │
   └─ TodoDispatchContext
      ├─ onCreate
      ├─ onUpdate
      └─ onDelete
         │
         ├─ Editor
         └─ List
            └─ TodoItem
```

---

**7. 각 컴포넌트에서 필요한 Context만 사용**

`Editor`는 Todo 목록이 필요하지 않고 `onCreate`만 필요하다.

```jsx
const { onCreate } = useContext(TodoDispatchContext);
```

`List`는 `todos`가 필요하다.

```jsx
const todos = useContext(TodoStateContext);
```

`TodoItem`은 수정과 삭제 함수가 필요하다.

```jsx
const { onUpdate, onDelete } =
  useContext(TodoDispatchContext);
```

---

**8. 분리했을 때의 장점**

```text
todos 변경
→ TodoStateContext 변경
→ State Context를 사용하는 컴포넌트 영향

TodoDispatchContext
→ 함수 객체가 그대로라면 값 유지
```

따라서 `todos`를 사용하지 않고 함수만 사용하는 컴포넌트가 **State Context 변경 때문에 함께 영향을 받는 것을 줄일 수 있다.**

---

**9. React.memo와의 관계**

`TodoItem`에 `memo`를 적용한 상태에서도 Context 값이 변경되면 해당 Context를 사용하는 컴포넌트는 다시 렌더링될 수 있다.

```text
React.memo
→ Props 기반 불필요한 렌더링 감소

Context 분리
→ 불필요한 Context 변경 영향 감소
```

두 최적화는 서로 다른 원인을 다룬다.

---

**10. 전체 최적화 구조**

```text
useReducer
→ todos 상태 변경 관리

useCallback
→ onCreate / onUpdate / onDelete 참조 유지

useMemo
→ Dispatch Context value 객체 유지

TodoStateContext
→ todos 전달

TodoDispatchContext
→ 상태 변경 함수 전달

React.memo
→ TodoItem 불필요한 렌더링 감소
```

---

**11. 핵심 정리**

* 하나의 Context에 자주 바뀌는 값과 안정적인 값을 모두 넣으면 불필요한 리렌더링이 생길 수 있다.
* `TodoStateContext`에는 `todos`를 넣는다.
* `TodoDispatchContext`에는 `onCreate`, `onUpdate`, `onDelete`를 넣는다.
* 함수는 `useCallback`으로 참조를 유지할 수 있다.
* 함수들을 묶은 객체는 `useMemo`로 메모이제이션할 수 있다.
* 컴포넌트는 자신에게 필요한 Context만 사용한다.
* Context 분리는 **Context 변경의 영향을 필요한 컴포넌트로 좁히는 것**이 핵심이다.
* 핵심 구조는 **`State Context / Dispatch Context 분리`**이다.
