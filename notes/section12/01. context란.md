# Section 12 - 1. Context란

**1. React Context란?**

React Context는 **컴포넌트 간에 데이터를 전달하는 방법 중 하나**이다.

기존에는 주로 Props를 사용했다.

```text
부모
↓ Props
자식
```

하지만 컴포넌트 구조가 깊어지면 Props 전달이 복잡해질 수 있다.

---

**2. Props Drilling**

예를 들어 `App`의 데이터를 가장 아래의 `C`에서 사용한다고 하자.

```text
App
↓ data
A
↓ data
B
↓ data
C
```

`A`, `B`가 데이터를 직접 사용하지 않더라도 다음 컴포넌트로 전달해야 한다.

이처럼 **여러 단계에 걸쳐 Props를 계속 전달하는 현상**을 `Props Drilling`이라고 한다.

---

**3. Context를 사용하는 이유**

Context를 사용하면 중간 컴포넌트가 Props를 계속 전달하지 않아도 된다.

```text
Props 방식

App
↓
A
↓
B
↓
C
```

```text
Context 방식

Context
↓
필요한 컴포넌트
```

즉, Context는 **Props Drilling을 줄이는 데 사용할 수 있다.**

---

**4. Context의 개념**

현재 단계에서는 Context를 **여러 컴포넌트가 접근할 수 있는 데이터 보관 공간** 정도로 이해하면 된다.

```text
        Context
      ┌────┼────┐
      ↓    ↓    ↓
      A    B    C
```

Context가 제공하는 범위 안에 있는 컴포넌트들이 필요한 데이터를 사용할 수 있다.

---

**5. Todo 프로젝트와 연결**

기존 Todo 프로젝트에서는 다음과 같이 함수를 전달했다.

```text
App
↓ onUpdate / onDelete
List
↓ onUpdate / onDelete
TodoItem
```

`List`가 `onUpdate`, `onDelete`를 직접 사용하지 않고 `TodoItem`에게 전달만 한다면 Props Drilling 구조가 된다.

컴포넌트 계층이 더 깊어질수록 이런 전달 과정이 더 복잡해질 수 있다.

---

**6. Props와 Context**

```text
Props
→ 부모에서 자식으로 직접 데이터 전달

Context
→ 여러 단계의 Props 전달을 줄이는 데 사용
```

Context가 Props를 완전히 대체하는 것은 아니다.

가까운 부모와 자식 사이의 단순한 데이터 전달은 Props가 여전히 자연스럽고, 여러 단계에서 공통으로 필요한 데이터를 전달할 때 Context를 고려할 수 있다.

---

**7. 핵심 정리**

* Context는 컴포넌트 간 데이터를 전달하는 방법이다.
* Props는 부모에서 자식 방향으로 데이터를 전달한다.
* 여러 단계에 걸쳐 Props를 전달하는 것을 `Props Drilling`이라고 한다.
* 중간 컴포넌트가 사용하지 않는 Props까지 전달해야 할 수 있다.
* Context를 사용하면 이러한 Props Drilling을 줄일 수 있다.
* 현재 단계에서는 Context를 **여러 컴포넌트가 사용할 수 있는 데이터 보관 공간**으로 이해하면 된다.
* Context는 Props의 완전한 대체재가 아니라, 필요한 상황에서 함께 사용하는 도구이다.
